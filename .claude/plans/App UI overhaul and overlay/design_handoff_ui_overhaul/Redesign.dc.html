4 Radar ping, style B — five rings, two mapping logics (A/B of your question)
Your three questions, answered in the demos
· Which ring for quiet vs loud? Loud should sit inside, near you — in games loudness is a distance proxy: approaching footsteps get louder and closer. Putting loud on the rim would read backwards. 4b shows that mapping; quiet sounds appear on the outermost ring and march inward as they grow.
· One ring or all of them? Both work, so both are live: 4a lights every ring up to the level (meter logic — more rings = louder, very legible in peripheral vision), 4b lights only one (map logic — ring = distance, cleaner with several simultaneous sounds).
· Rings only ever light in the sound's 45° direction sector, never the whole circle; the rear 45° wedge stays dark (7.1 has no rear-center). Verdict: not a bad idea at all — my pick is 4b for hunting threats, 4a if you care most about how loud. Could ship as "Radar ping (meter)" and "Radar ping (distance)" styles next to 2g.

3 Game detection & audio capture — why it stayed dark in-game, and per-game profiles
Root cause, from the code
· Speakers.cs → SelectDevice() locks onto one endpoint: your configured device, else the first 8-channel device it finds, else the Windows default — and only ever reads that endpoint's meter. If the game plays to your headphones while an idle 8-channel virtual cable sits in the list, auto-detect grabs the silent cable → the overlay never lights up. Recovery logic only handles device lost, never wrong device.
· ProcessMonitor.cs polls every 2 s but only watches exes that already have a profile — it can't discover a game it hasn't been told about.
· The fix uses the same safe WASAPI layer: audio sessions carry a process id and their own meter, so the app can find "cs2.exe is making sound on Headphones" and read that — no game hooks, same accessibility story. Session discovery doubles as game detection, which powers the per-game profile prompts in 3c / 3d.
3a Audio & device page (in the 2a shell) — three capture modes; "Follow the game" is the zero-setup fix. Live signal check proves audio is arriving.
